Rules

**Dashboard**

Cards should be set in the order in which they are outlined below. There are some exceptions to this rule, when they exist they will be outlined within the section to which they apply. 

When the employee logs in, they should initially only see two sections \- 1\. Their personal profile link & a ‘Start your day’ button that will ‘clock’ them into their shift. Time between when they ‘clock in’ to their shift, and when they complete the ‘end of day’ card should be logged on their profile and for the admin. This information should be logged for the admin in 14 day segments and sorted by each employee. Segments begin on a Wednesday and run for 14 days through the second Tuesday \- for example, April 29th, 2026 through May 12th, 2026\. And May 13th 2026, through May 26th 2026 are both 14 day segments that should be tracked separately. Admin will indicate these segments in the calendar. Note, admin can also make some adjustments, for example, when an employee is new, and starts in the middle of a segment, the admin may roll their hours to be counted in the following full segment. But unless otherwise indicated, segments stand. When the user ‘clocks in’ they will not see any of this, but they will see their assigned cards for the day appear below. Users MUST complete cards in their assigned order. 

In addition to tracking the full time of a shift, and the time each card is ‘open’(in use and being performed by the user), the system should also track and log time spent between cards. There should be no more than 1 minute between most cards, with an exception for two 5 minute breaks between cards per shift, and one 15 minute break between cards per shift. Any additional breaks, or longer breaks, should be logged on the employee profile, and trigger a note for admin review. Repeated instances of this should trigger an additional log and additional note for admin review. 

Cards that have been completed should be left on the users dashboard until the shift has been ‘wrapped’. Upon completion of a shift, all cards should be archived for future admin review and reference. Archived cards should be searchable by date, guest, type, location, and user. There should also be a separate section where archived cards with exceptions can be reviewed \- time, task list, note, maintenance, reassigned \- are all exceptions. 

Employee profiles will be set with a ‘standard’ for how much each employee should be assigned on a given day. This will help the system distribute cards, and also notify the admin when more staff need to be scheduled for a shift. The standard for now should be that 1 housekeeping user can handle up to 5 departures, 10 stayovers, and 15 daily tasks per shift. For shifts with less, weekly and monthly tasks can be assigned, along with deep cleans, as needed. For days with more, the admin should be notified with as much notice as possible to schedule additional staff, and should be reminded daily until there is enough staff scheduled to handle the load of the day. 

Each card should log the time it is started, the time it is completed, how long it took, and who the card was assigned to. 

Each card also has a pause function \- the employee can pause a card \- this time should be logged and tracked. When an employee ‘unpauses’ a card, it should require a note as to why the card was paused. These notes should be tracked on the employee profile for admin review, but do not need to trigger an admin note. Pausing will only pause the time in the specific card, and time paused should be tracked as time between cards. 

If cards are ever reassigned by the admin to another user, the details should be logged for both users \- they should be logged on the card together, and logged separately to the employee. 

The system will log a number of items for admin review, but the only things that the system logs that the user should be able to see is notes they create, and items they check as complete. Logs like user, time, errors, should only be visible to the admin. 

The Daily Details sections should always be pinned to the top of the employees day above the cards. This sections includes: Notes from admin on the day

Pulled from google, this should list anything fun or noteworthy happening in town, as well as any holidays.   
		**Notes**: This is for notes (currently placed by the admin, possibly eventually input from Resnex, notes on guests that are arriving or departing that should be noted for the staff)

The order of cards is set by rules, but should rotate as cards are completed to keep the open cards at the top. 

Admin should be able to review time logs by user and by location \- for example, it should show how long each card took a user, but also how long each location is taking per card/shift. This will be a running list on the admin panel. 	**Tasks**  
Tasks will be pulled from a list of daily, weekly, and monthly tasks. Daily tasks must be completed daily. They should be assigned to the staff and bundled based on location \- for example, hallway tasks should be assigned together and lobby tasks should be assigned together. The tasks will be pulled from the knowledge base & will link to this information, should the user click ‘details’. The knowledge base will outline a schedule of tasks. Tasks can be overridden or skipped by the admin. Tasks that are missed or incomplete, should trigger a review for the admin and should be prioritized the following shift. Time for each task will vary greatly, so there is no set rule for the time a daily task card should take, however, the system should recognize the time required for each task from the knowledge base, total the times for the assigned tasks, add 5 minutes for card use. Anything over under 20% of this time should trigger a note for admin review. Three repeated instances of this in a 30 day period should trigger an additional note for admin review and be logged on the employee profile.   
These tasks should be reassigned and updated realtime as employees begin to complete their other cards. If one user is still working on their departure cards, some of their daily tasks should be reassigned to a user who is already working on their daily task card. The system should work to assure all users working on a given shift make it to their End of Day card as close to each other as possible. When there are more than two housekeepers on a shift, the two primary users should be assigned the stayovers and arrivals, and assigned less daily tasks \- in this instance, more daily tasks should be assigned to the secondary users for the shift. If there are days when there are more than one housekeepers on a shift, and a single user completes 80% or more, or 20% or less of the daily tasks assigned to the team as a whole, this should trigger a note for admin review.
